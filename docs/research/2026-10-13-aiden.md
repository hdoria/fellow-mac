# Fellow Aiden no macOS: pesquisa de viabilidade

Data: 2026-10-13. Status: pesquisa estática; nenhuma conta autenticada e nenhuma cafeteira acionada.

## Resposta à pergunta inicial

- O [Fellow oficial](https://apps.apple.com/us/app/fellow/id6612024910) aparece como exclusivo para iPhone. A [página do fabricante](https://fellowproducts.com/pages/app) apresenta seus apps móveis.
- O [Detent Coffee](https://apps.apple.com/my/app/detent-coffee/id6764680211) declara envio de perfis à Aiden e lista macOS 15.6 ou superior em Apple Silicon. A própria loja informa que foi projetado para iPad e não foi verificado para macOS. Não encontramos evidência de uma interface dedicada à menubar.
- As buscas realizadas não encontraram um cliente nativo de menubar para Aiden. Isso não prova que nenhum exista.

A extração usou `unzip`, o formato de bytecode documentado pelo [Hermes](https://github.com/facebook/hermes/blob/main/include/hermes/BCGen/HBC/BytecodeFileFormat.h) e [hermes-dec](https://github.com/P1sec/hermes-dec/tree/a0f18f97ab661eb8ed659c8c683a0d21ea619e69), sem executar o app. Os resultados foram confrontados com implementações comunitárias.

## Contrato observado

Base dos caminhos abaixo: API `/v2`. O app se comunica com a nuvem; não foi identificado um contrato local/LAN utilizável nesta pesquisa.

| Operação | Método e caminho | Grau de evidência |
| --- | --- | --- |
| Login | `POST /auth/login` | Função Hermes 14026: `email` em minúsculas, `password`, `timezone` |
| Renovar sessão | `POST /auth/refresh-token` | Função 14030: JSON `refreshToken` |
| Dispositivos | `GET /devices?dataType=real` | Disassembly de `getDevices` |
| Estado do aparelho | `GET /devices/{id}?dataType=real` | Função 18498 |
| Perfis | `GET/POST /devices/{id}/profiles`; `GET/PATCH /devices/{id}/profiles/{pid}` | Funções 21131, 21135, 21139, 21151; ramo sem prefixo de produto |
| Compartilhar perfil | `POST /devices/{id}/profiles/{pid}/share` | Função 21155 |
| Importar link | `GET /shared/{drop_type}/{pid}` | Código Home Assistant; tipo padrão `aiden` |
| Agendamentos | `GET/POST /devices/{id}/schedules`; `PATCH/DELETE /devices/{id}/schedules/{sid}` | Funções 33315, 33319, 33323, 33327 |
| Preparo com parâmetros | `PATCH /devices/{id}/start[?confirm=true]` | Funções 18518, 18466, 33246: corpo `profileId`, `amountOfWater` truncado para inteiro |
| Instant Brew | `PATCH /devices/{id}/start[?confirm=true]` | Função 18522: não envia corpo |
| Parar | `PATCH /devices/{id}/stop` | Função 18526: sem corpo; eficácia não validada |
| Selecionar perfil | `/devices/{id}/selectedProfile?profileId=...` | Existe no app; documentação comunitária relata rejeição pelo gateway |

As duas variantes de início explicam a divergência entre clientes comunitários: há função com corpo e função sem corpo no pacote. Encontrar a função não comprova seu suporte em todos os firmwares nem seu efeito físico.

O interceptor constrói Authorization com Bearer e access token. Fontes de perfil também contêm ramos para outros produtos; não aplicar prefixos ou `settingsVersion` à Aiden sem confirmar o discriminador. O endereço base acima foi encontrado como configuração no DEX; a seleção de ambiente em execução não foi observada.

A [nota técnica v2 do Home Assistant](https://github.com/kristofferR/FellowAiden-HomeAssistant/blob/de409f8df513a4ef72389e43f6bc5ffd1883bb75/docs/fellow-api-v2.md) e o [README do mesmo commit](https://github.com/kristofferR/FellowAiden-HomeAssistant/blob/de409f8df513a4ef72389e43f6bc5ffd1883bb75/README.md#L253) registram resultados relevantes:

- Início de Instant Brew documentado para firmware 1.5.16 ou superior, usando configuração já existente na cafeteira.
- Parada não cancelou de forma confiável o preparo observado. Não oferecer uma garantia de parada no nosso app.
- O estado v2 deve prevalecer sobre indicadores antigos que podem ficar desatualizados.
- `brewStartTime` e `brewEndTime` podem mudar fora de um ciclo; sua subtração isolada não prova duração de preparo.
- Notificações FCM indicam necessidade de atualizar dados; não substituem a leitura do estado.

Quando fontes divergem, o pacote 1.4.6 e a documentação v2 com observações explícitas prevalecem sobre README ou clientes baseados em v1 para orientar novos testes. Nenhum deles substitui validação na cafeteira do usuário.

## Implementação macOS

[MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra) fornece presença nativa na menubar, incluindo estilo de janela. `LSUIElement` permite um utilitário sem ícone permanente no Dock. [Keychain Services](https://developer.apple.com/documentation/security/keychain-services) será usado para credenciais persistidas.

O diretório do projeto estava vazio e sem Git. Verificação local: Xcode 27.0 (27A266a), Swift 6.4, SDK macOS 27.0 e host arm64. O seletor global aponta para CommandLineTools; usar `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` nos comandos que exigem Xcode, sem alterar a configuração global.

## Limites e próximo teste

Não houve captura de tráfego autenticado, prova de login, leitura da cafeteira do Hugo, teste de comando ou teste do Detent instalado. Para integração real, a conta deverá ser conectada pela interface local do futuro app. Primeiro validar leituras; depois operações explicitamente selecionadas pelo usuário.

Publicar apenas nosso código e documentação de interoperabilidade. Não incluir APK, bytecode, fontes, imagens ou outros assets proprietários.
